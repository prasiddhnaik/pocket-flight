src/main.tsx and src/vite-env.d.ts remain at the source root. lab/ remains the private wind tunnel, with a separate Vite build and workers. Existing test and script paths remain stable.

Choose the feature that owns a change. Keep its styles and private helpers together. Use direct imports to the owning file; the directory structure does not require new wrappers or public barrel modules.

The shared flight model is used by both the game and lab. A change to shared simulation or aircraft data therefore needs both builds. HUD code consumes game snapshots; Studio reconstructs recorded aircraft and world state.

Scope of this pass

This records the navigation pass. Scene Studio was subsequently split into smaller modules; see the Studio refactor report for the current structure and offline checks.

71 loose source files were relocated into eight feature folders alongside the existing HUD folder. Imports, HTML module entries, authoring destinations, source-fingerprint lists, and documentation references were updated.

Function bodies, styling, and measured runtime JSON data were preserved. The six public HTML entry URLs, public assets, browser storage keys, project schema, and IndexedDB version remain unchanged. Pre-existing working-tree edits travelled with their files.

Source reorganization does not claim to complete the deeper architecture redesign: large app/game/Studio modules still exist. Their responsibilities can be separated in later focused changes.

Repeatable navigation check

After moving a source file, update all importers, the root HTML entry if applicable, generators that write data beside it, and documentation links. Run bun run repo:check, affected tests, and the relevant production builds. Refresh code-review-graph after structural changes.

The migration record is an observed result, not a requirement to keep the current folder list forever. Prefer meaningful ownership and a small change surface when adding a new feature.
