Private wind-tunnel optimization

The optimization removes redundant airflow reconstruction, reduces draw calls and GPU geometry objects, moves new traces off the UI thread, and stops rendering settled inactive views. Aircraft detail and analytical panel counts remain intact.

What changed

  • Compatible opaque static meshes are batched by material, attribute layout and wing membership. Transparent glazing, movable rig/fan hardware and mirrored meshes remain separate. Every runtime triangle and precise aircraft bounds are preserved.
  • Fixed shadows update only when geometry, pose or visibility changes. The animated fan rotor does not cast a frozen shadow.
  • A bounded reference-solution cache rescales circulation by speed and forces by density times speed squared. Every input still passes validation. Cached results match independent fresh solves over the supported speed/density endpoints and −8°, 0°, +8°.
  • Speed and density retain existing stream paths. New geometry, angle and panel count use a worker. Only the newest pending request is queued, stale responses are ignored, and the worker terminates when the scene is disposed. The eight-condition path cache is cleared when aircraft changes.
  • Path animation reuses sample storage and interpolates six unique trail points instead of eleven. Static line buffers are packed directly into typed arrays.
  • Paused or fully hidden animation views render on demand. Camera, viewport, layer and result changes still redraw. Material shaders are invalidated only when transparency actually changes.
  • Development aircraft responses use ETag revalidation, reusing unchanged files while detecting source edits.

Verification

107 tests pass with 7,907 assertions; the private production build passes. The 23 existing browser acceptance checks pass with zero errors. Twelve additional browser checks verify reuse, bounded GPU allocations/cache size, rapid-input invalidation, rapid aircraft switching, inactive rendering, paused-camera redraw and animation resumption.

The aerodynamic model has the same main-wing scope and exclusions. Rendering optimizations do not establish full-aircraft CFD or flight-model accuracy. Detail was not decimated and panel resolution was not lowered. Vite still reports a large main Three.js bundle; splitting the tracing worker isolates computation rather than eliminating the renderer download.
