Aurelia avionics data contract

The five mounted displays render a supplied immutable AureliaAvionicsState. They do not generate aircraft motion, engine readings or map movement. avionics-demo.ts provides sample data exclusively for the reference viewer; the game integration supplies telemetry, systems and map geometry.

Ownership and entry points

  • avionics-state.ts: snapshot types, SI telemetry adapter, map projection and update cadence.
  • avionics.ts: canvas renderer and mounted display lifecycle.
  • avionics-demo.ts: deterministic demonstration data.
  • aurelia-reference.ts: demonstration clock, pause, visibility and disposal.
  • dashboard.ts: lower instrument-panel datum and hull-fitted housing.

Feed real telemetry

import { AureliaAvionics } from "./avionics";
import { aureliaAvionicsFromFlight } from "./avionics-state";

// telemetry, systems and map come from their simulation owners.
const initial = aureliaAvionicsFromFlight(telemetry, systems, map);
const displays = new AureliaAvionics(aircraftRoot, initial);

// Supply a new immutable snapshot after the simulation step.
// Increment telemetry.revision whenever any sensor, systems or map data changes.
displays.update(aureliaAvionicsFromFlight(telemetry, systems, map));

// When removing the aircraft:
displays.dispose();

The live game does not yet instantiate this reference-model cockpit. The adapter is the integration boundary; connecting it to the gameplay aircraft and map is a separate integration step. Do not import demonstration defaults into that integration.

Units and inputs

Input Convention
position, velocity Metres and metres/second. +Y up, +X east, -Z north, same local origin as the map.
indicatedAirspeedMps Actual indicated airspeed in m/s; separate from horizontal groundspeed. The adapter does not mistake total true airspeed for IAS.
yaw, pitch, roll Radians. Pocket Flight positive yaw turns toward -X; compass heading is normalized negative yaw in degrees.
time, revision Simulation seconds and a changing numeric revision. Revision permits new data at unchanged simulation time. Rewinds render immediately.
gear, flaps Actual actuator fractions, 0–1; supply actual positions rather than commands.
systems Independent left/right N1/N2 %, ITT °C, oil psi/°C and fuel lb; bus volts; guidance modes, AP/YD status, selected altitude ft, director attitude radians; COM MHz, baro inHg, four-character transponder code and mode; UTC seconds since midnight.
navigation World-space route waypoints, runway endpoint pairs and terrain polygons. Range is nautical miles to the outer ring. Heading-up and north-up are supported.

The adapter converts metres to feet and vertical m/s to ft/min, derives horizontal groundspeed from velocity, and copies the aircraft's actual X/Z position. It supplies no invented engine or radio readings. A direct snapshot may also use source: "replay".

Map and rendering behavior

All route, runway and terrain vertices use one world-to-screen projection relative to the current aircraft position. Moving the aircraft updates the map even when the displayed time stays fixed, provided the revision changes. Map range, orientation and desired track are supplied variables. Missing geometry produces an empty map area without fictional waypoints.

Use immutable snapshots and increment revisions for changing map geometry or systems. Rendering is capped at 20 Hz when focused and 2 Hz in other views, using a wall clock independent of simulation time. Unchanged frames are skipped; actuator changes and rewinds update immediately. A forced update supports deterministic inspection exports. Hidden documents do not redraw.

Textures replace the existing glass faces; they add no overlay planes. Eight reusable canvases serve five screens and three legend plates. Dispose restores the original mesh materials and geometry and releases textures. The GLB contains editable geometry and bindings; the TypeScript runtime supplies the animated textures.

Verification

bun run aurelia:reference-check rebuilds the asset and runs geometry, floor, attachment, map projection, data-input and dashboard tests. Supplied-data rendering is tested through recorded canvas commands, including independent engine values, variable radios, a changed altitude at unchanged time and a runway projected from world coordinates. Browser inspection separately verifies visible placement and animation.
