Finch U–2 engineering baseline

Physical force model implemented; aerodynamic accuracy remains provisional.
Finch now uses measured runtime wing geometry, body-frame airflow, forces in newtons, a conceptual mass budget, density-dependent lift and propulsion, induced drag, and an angle-of-attack stall curve. Beginner assist is on by default and can be switched off in Settings.

The user selected Finch as the first aircraft and physical flight with optional beginner assist. This work applies the aircraft-design handbook, especially sections 4, 5, 7, 8, 17, and 19. The existing asset is measured and tied to its force model. No new GLB or CAD rebuild is delivered in this milestone.

Current fleet revision: Fleet dynamics validation records the shared mass, CG, full inertia tensor, aerodynamic moments, physical actuators and fuel model now used by all four aircraft. This page retains Finch’s original 800-section geometry measurement; the runtime station-integrated private-tunnel wing area is 16.129 m², a 0.03% method difference.

Conceptual loading and propulsion

These values are proposed engineering inputs for this fictional trainer, not measured masses or manufacturer specifications. The mass budget is explicit so it can be revised instead of hidden inside a lift multiplier.

The geometric ground-load estimate places approximately 27.2% of static weight on the nose gear at this CG. This only checks support geometry. Loaded mass determines translation; CG affects aerodynamic and thrust-line moments, and component cuboids contribute a full parallel-axis inertia tensor. Wheel reactions oppose unsupported power-only rotation.

Propulsion assumes 135 kW shaft power, 0.78 propeller efficiency, and a 3,350 N static-thrust cap. Thrust is bounded by both that cap and available power divided by airspeed. A naturally aspirated density correction is applied. The concept power rating was revised after a binary keyboard takeoff test showed inadequate climb margin at the first Palm Bay checkpoint; it is a tuning assumption, not a measured or certified engine rating. Beginner assist limits positive keyboard elevator during rotation and climb and trims relative to the air-relative flight path. Manual mode retains unrestricted elevator input. Fuel consumption is modeled at an estimated full-power 0.0075 kg/s. An RPM/pitch efficiency map, slipstream and propeller reaction torque remain unresolved.

Repeatable workflow

  1. Run bun run finch:measure after any asset change. Reconcile dimensions, reference area, chord, and wheel datums with src/aircraft/finch/finch-design.ts.
  2. Revise the conceptual loading budget and propulsion assumptions, keeping units and provenance explicit.
  3. Run bun run finch:verify for force relationships, bank/wind invariance, stall, power limits, asset consistency, takeoff, landing, glide and damage.
  4. Run bun test --timeout 30000 and bun run build; distinguish pre-existing scenery failures from flight regressions.
  5. Fly the browser aircraft with real controls. Check assist persistence, takeoff, turns, recovery, approach and replay before approving handling.

Verification record

See the current fleet validation report for the latest passing suite, builds, real keyboard departures, seeded landing checks and 32 unassisted trim conditions. Finch’s local keyboard departure reaches the first checkpoint, remains undamaged and unstalled, and climbs above 55 m after 20 seconds.

Remaining accuracy work

  1. Choose or substantiate airfoil sections and obtain Reynolds/configuration-specific polars. Validate wing incidence, twist/washout, and actual surface hinge geometry.
  2. Calibrate the implemented CG-dependent moments, inertia, damping and stability derivatives against independent data. Resolve local tail and fuselage flow interference.
  3. Extend the implemented actuator and engine-spool model with propeller slipstream, torque and RPM/pitch efficiency.
  4. Validate cruise trim, climb, glide ratio, turns, stall recovery, multiple loading cases and landing distances against a mission design sheet.

Peregrine, Aurelia, and Stormbird now use the same force and rigid-body moment integration with separate component loading, wing geometry and propulsion data. Aurelia is explicitly configured without afterburner.
