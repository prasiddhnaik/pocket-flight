1. Redesign Settings

Status: requested by the user; queued. Purpose: make controls, assistance and other preferences easy to find and understand as the game gains more physical aircraft behavior.

Confirmed requirement: Settings → Controls

ControlBehaviorState
Automatic gear and flapsOn: the game commands deployment. Off: the player commands gear and flaps. Both use the same physical actuator and contact model.Accepted toggle. Implementation default: automatic on for new players.
Beginner flight assistanceSeparate control for stabilization, coordinated-turn help and automatic trim. It does not change the gear/flap command mode.Existing capability to integrate into Controls.
Manual gear/flap actionsShow applicable actions and keyboard/touch bindings. Gear command changes deployment; flap commands select the aircraft's supported settings.Required companion work for manual mode; exact bindings and flap presets to be set during implementation.

Redesign checklist

  • Bring the editable controls and their help into Settings → Controls, with useful entry points from the flight and pause screens.
  • Make automatic/manual configuration and flight assistance clearly separate, with concise labels explaining their effect.
  • Keep the control layout readable on desktop and mobile. Provide keyboard navigation, visible focus and accessible toggle states.
  • Review the current mix of time of day, audio, soundtrack, fullscreen, assistance and paint. Propose a clear grouping before redesigning their presentation.
  • Save preferences consistently, restore valid defaults and include a reset for control preferences.
  • Prevent settings clicks and key presses from becoming flight commands. Preserve pause/focus behavior.
  • Show actual configuration state during flight, including gear/flap transitions; update controls help and takeoff/landing prompts to match the selected mode.

Dependencies and delivery order

The configuration-mode setting and manual commands belong to the first flight-physics release. They require the common actuator command path and actual-state feedback. The wider settings redesign is a queued work item: refine its layout after the final set of first-release controls is known.

Source starting points: pocket-flight-site/src/App.tsx currently has separate Controls and Settings panels; src/game.ts maps keyboard/touch commands; src/physics.ts automatically commands gear and approach flaps. Verify the current working tree before implementation because it contains active changes.

Acceptance criteria

  • A player can find the automatic gear/flap toggle under Settings → Controls and identify the selected mode.
  • Changing configuration mode leaves the beginner-assistance preference unchanged, and vice versa.
  • Manual mode preserves current configuration until the player commands a change. Automatic mode resumes through normal deployment rates.
  • Preferences survive reload; unavailable aircraft actions are handled clearly.
  • Settings, keyboard/touch actions, HUD configuration feedback and controls help agree.

2. High-altitude flight

Status: requested by the user for a later expansion. Dependency: complete the island flight model and its recorded acceptance evidence first.

  • Choose a higher-altitude gameplay envelope and world boundary suitable for the expanded flight experience.
  • Review atmosphere, propulsion and aerodynamic data against that envelope. Existing altitude maps are a starting point, with their transfer assumptions checked for each fictional aircraft.
  • Calibrate climb, trim, control authority, glide and fuel behavior across altitude and loading.
  • Review camera, instruments, world scale, mission routes and floating-point precision as the flight space grows.
  • Record numerical and in-app browser evidence for aircraft that support the expanded envelope.

Exact altitude range, eligible aircraft and gameplay content will be planned when this expansion is scheduled.

3. Supersonic flight

Status: requested by the user for a later expansion. Dependency: a stable common flight/contact core and an explicitly selected high-speed aircraft envelope.

  • Research and calibrate the appropriate compressibility, wave-drag, stability/control and installed-propulsion models.
  • Define which aircraft support the new speed range and provide suitable data instead of treating current estimated drag rise as validation.
  • Validate acceleration through the transition, trim/control response and deceleration back to the landing envelope.
  • Check swept collision handling, time-step stability, world traversal and camera readability at the expanded speeds.
  • Review audio, effects and mission scale once the accepted physical behavior is established.

Exact Mach range and the relationship to the high-altitude expansion remain future planning decisions. Neither expansion is required for the first island release.
