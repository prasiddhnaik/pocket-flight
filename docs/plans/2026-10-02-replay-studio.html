Pocket Flight: Replay Studio

2 October 2026 · Implementation brief

Current scope

Only flight replays. Save recordings and editing projects in browser storage. Combine saved flights into one film, preserve original flight data, and export edited video. Keep the existing compact flight HUD. Use Finch only for live verification; do not test jets.

Design

Part Player experience Implementation
Library Reopen saved flights after reload, rename recordings, view storage usage, download and restore backups. Versioned flight frames in transactional IndexedDB storage. Archive on pause/end, before restart, and every ten seconds. Storage failure leaves current footage usable.
Editor Preview, sequential clip timeline, scrubber, trim, split, reorder, duplicate, camera shots, speed, titles, audio level, undo/redo, project autosave. React editor and pure timeline functions. Projects retain immutable copies of source recordings. Independent renderer samples recorded poses; background game rendering is suspended while editing.
Export 720p video with camera cuts, playback speed, titles, and synthesized game audio. Progress, cancellation, and download. Preload every required aircraft before recording. Canvas capture and MediaRecorder, choosing MP4 when supported or WebM as fallback. Tab hiding cancels export to avoid missing footage.

Implementation sequence

  1. Storage-safe schema, validation, IndexedDB library, and clip-time mapping.
  2. Automatic archiving and suspension integration in the game.
  3. Library, editor controls, preview, captions, and export.
  4. Build, focused storage/timeline tests, Finch browser checks, mobile layout, video inspection.
  5. Commit and push only replay changes, preserving unrelated local work.

Files

replay-data.ts, replay-library.ts, studio-model.ts, replay-preview.ts, ReplayStudio.tsx, and studio.css. Focused integration in game.ts, App.tsx, audio.ts, replay.ts, and replay-export.ts.

Acceptance

Pause a Finch flight, reopen its recording after reload, combine two saved flights, trim and split clips, change cameras and speed, add titles, preview the film, undo edits, and download a valid video. A corrupt backup or failed save must produce a usable error without overwriting valid data.

Storage details

The library stores flight data and edit decisions rather than rendered movies. Storage belongs to a browser and site origin, including port. Clearing site data removes saves. Include backup downloads and a request for persistent storage where supported.

Verification limits

Video capture occurs in real time while the tab stays visible. The recorder retains the latest thirty minutes of long free flights. Aircraft and scenery updates may affect how older recorded flight data is rendered. Jet replay preview and mobile video encoding are not part of live verification for this pass.
