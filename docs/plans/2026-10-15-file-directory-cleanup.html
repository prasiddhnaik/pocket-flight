Recommended sequence

  1. Capture a baseline. Record free disk space, directory sizes, Git status, and hashes or backup locations for large editable files. Keep cleanup separate from ongoing feature edits.
  2. Map dependencies and ownership. For each large or confusing directory, identify scripts, docs, runtime URLs, and build steps that refer to it. Confirm whether local Python/browser tools or generated evidence are in use.
  3. Recover space from confirmed local caches. After checking running processes and regeneration instructions, clear only confirmed-unused dependency/install caches. Reinstall with Bun from the lockfile if the project needs to run again. Keep graph data unless it is a measured space priority.
  4. Sort output/ by value. Keep evidence referenced by README/docs and any deliverable exports. For old, unreferenced captures, compare dates and content; move chosen archives outside the working repository only after making and checking a recoverable copy.
  5. Review nested snapshots and Blender backups. For assets/map-verification/ and *.blend1 files, verify provenance, compare with current sources, search for inbound links, and make a separate archive before any removal. Do not prune aircraft references, editable masters, or validation records as a bulk operation.
  6. Improve navigation only where it pays off. Keep the existing top-level layout. If repeated loose reports or artifacts remain hard to find, group future items under their current docs/ or artifacts/ categories, updating every link in the same change. Avoid broad moves of source files and assets.
  7. Close out the pass. Compare before/after sizes and Git status, confirm archived files open from their new location, and ensure documented commands and runtime asset references still resolve. Report recovered disk space separately from data merely moved elsewhere.

Decision gates

  • Archive candidates only after confirming they are not active, not the sole copy, and not needed by a script, README, report, or runtime route.
  • Prefer moving to a dated archive outside the repository over deletion when a file has historical or evidentiary value. Verify the copy before removing the original.
  • Do not stage, commit, reset, or rewrite the existing dirty work as part of directory cleanup.
  • Measure actual disk-space recovery after cleanup; a move to another local folder improves repository clarity but does not free disk space.

Success criteria

  • Unneeded local caches are removed only after their use and recreation path are confirmed.
  • Useful outputs, source models, references, validation artifacts, runtime files, and all pre-existing work remain recoverable.
  • Any archive has a clear date/name and a verified copy; links are updated where files move.
  • The repository has a short, understandable top-level layout, and before/after directory sizes and Git status are recorded.
