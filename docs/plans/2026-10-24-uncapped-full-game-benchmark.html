Plan: uncapped full-game benchmarks

24 October 2026 · Pocket Flight · Prepared before implementation

Goal and current evidence

Remove the test browser's observed 30 FPS ceiling, then determine which existing engine and rendering experiments improve full-game throughput with Finch, physics, HUD and VFX running.

The previous empty about:blank control measured exactly 30 FPS. The runner records that control but currently continues without a cap-removal gate. It also reuses fixed output directories. Existing capped evidence must stay available for reference.

Recommended approach

Create a dedicated benchmark browser configuration that retains Chromium and the Metal GPU backend and adds --disable-frame-rate-limit. Chromium's own source says this switch removes scheduler frame limiting and also implies --disable-gpu-vsync. Verify behavior empirically before any long run. Chromium switch definition.

Use a separate browser session and a new timestamped output directory. Preserve the existing shared browser configuration and capped datasets. The game source and graphics defaults stay at the current baseline while the experiments run.

Execution sequence and gates

  1. Snapshot the experiment. Save browser configuration/version, launch flags, source fingerprints, dimensions, device/game pixel ratios, GPU identity and the variant list. Preserve previous results.
  2. Prove the cap is removed. Measure three short empty-page controls, an animated DOM element and a simple animated WebGL scene. Require blank-page median above 45 FPS and both active controls above 90 FPS, with visible documents and a hardware renderer. Check controls again after the comparisons. If the first flag does not work, try explicit GPU-vsync disabling and a separate hardware-accelerated headless configuration; record each attempt. Stop the long benchmark if active controls remain capped.
  3. Run a baseline flight smoke test. Verify the aircraft and HUD visually, confirm advancing fixed-step physics and HUD snapshots, and check console/WebGL errors. Confirm that browser controls have enough headroom above measured game FPS; results close to the control ceiling remain inconclusive.
  4. Rerun both full-game comparisons. Run the 12 collision trials and the 36 rendering trials, keeping the current 2-second warmup, 6-second measurement and 0.5-second GPU drain. Preserve alternating/rotating order and identical flight paths. Run comparisons sequentially without builds, tests or other agent-owned rendering sessions competing for resources.
  5. Validate and rank. Require complete unique round/scenario/variant coverage, zero hidden/invalid frames, advancing physics and HUD, visible aircraft/HUD, correct collision path, stable source hashes and zero browser errors/warnings. Save full JSON by direct download, plus screenshots and logs.
  6. Confirm a promising result. Compare median FPS, frame-time distributions, 1% low FPS, physics CPU time, render submission time, GPU query time and draw calls. A candidate with at least a 5% median FPS gain should improve all three initial paired rounds and avoid a material 1% low regression. Confirm the strongest candidate with a focused alternating baseline comparison using longer measurement windows. Otherwise report no consistent winner.
  7. Write the HTML findings. Distinguish confirmed improvements, inconclusive changes and diagnostics. Report visual costs alongside FPS. Label uncapped results as throughput in this local development build, rather than screen refresh rate or mobile performance.

Files and deliverables

  • scripts/run-engine-benchmark.ts: isolated launch configuration, cap/headroom gate, timestamped outputs, saved controls and launch metadata.
  • scripts/full-game-benchmark.tsx: only add narrow timing/confirmation options if required; preserve the real game loop and existing scenario paths.
  • A dedicated uncapped HTML report and raw evidence under output/full-game-uncapped/<run-id>/.
  • Update the benchmark workflow documentation after the new path works.

Completion criteria

A verified control above the old cap, 48 valid saved full-game trials, a repeatability-based ranking with visual tradeoffs, and an HTML report that states any remaining ceiling or noise. If the browser cannot be uncapped, preserve the failed control evidence and identify that limitation instead of repeating capped long runs.

Estimated long-run measurement time after the control succeeds: about seven minutes, plus browser startup, validation and any focused confirmation. No production deployment is part of this experiment.

Initial probe refinement: with the frame-limit flag, the unchanged blank page reached roughly 57 FPS while animated WebGL reached roughly 499 FPS on Metal. Idle-page pacing therefore cannot be the only uncapped gate; active DOM/WebGL controls and the real-game smoke test establish useful rendering headroom.
