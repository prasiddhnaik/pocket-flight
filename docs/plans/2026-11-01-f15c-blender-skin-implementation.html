F-15C Blender skin and animations: implementation plan

1 November 2026 · Implements the approved design, which executors read alongside this

Goal: Replace the F-15C's outer skin with a Blender model that matches the real aircraft, and add Blender-made gun barrel and missile launch animations, with flight handling unchanged.

Approach: A Blender script builds the skin and merges it with the CAD mechanical parts into the same game model, keeping every part name. Animations ship as clips; the game sets clip time from its own state, so live play and replays match.

Tools: Blender 5.2.1 Python (bpy, bmesh, numpy), Three.js r180, TypeScript, Bun tests, build123d CAD (unchanged).

Global constraints

  • Size: 13.04925 × 5.6261 × 19.431 m, pinned by tests/f15c-runtime.test.ts.
  • Flight numbers stay: wingArea 61.56022521316562, meanAerodynamicChord 5.250250398235864, quarterChordZ 1.2957202936056007, and everything in src/aircraft/f15c/design.ts.
  • Model budget: at most 506380 triangles and 13416284 bytes.
  • Part names stay, and moving nodes keep extras hinge_axis, travel_degrees, hinge. The root keeps gunMuzzle.
  • Every part touches or embeds into its parent. No floating parts.
  • Reference drawing stays out of public/ (CC BY-SA, see assets/f15c/references/CREDITS.md).
  • Strict TypeScript, never any. Use Bun. No dev server or build commands unless told. A temporary server for screenshots is stopped afterwards.
  • No commits unless the user asks. The checkout has existing uncommitted work; preserve it.

Review focus

Failure modes the design implies. Each has a test in the task named.

  1. Gear or canopy cycled in the aircraft viewer: doors must close flush on the new body, with nothing poking through (Task 3).
  2. An F-15C replay or Studio project saved before this work must still open and play (Tasks 3, 5).
  3. A short trigger tap: releasing during spin-up winds down from the current speed without a jump (Task 4).
  4. Different frame rates and pausing: barrel speed matches at 30 and 144 fps, and pausing freezes it (Task 4).
  5. A body missile fired on the ground or very low: its drop never goes below the surface, and the sandbox still works if the missile models fail to load (Task 5).

Task 4: Gun barrels

Files: scripts/build-f15c-skin.py, create src/aircraft/f15c/gun-spool.ts, modify effects.ts, powerplant-rig.ts, src/flight/cannon-effects.ts. Consumes: motion.gunAngle, motion.gunSpeed. Produces: class GunSpool { step(dt: number, firing: boolean): void; readonly speed: number; readonly blur: number }, with speed in radians per second.

  • [ ] Add clips and parts in Blender: Gun_spin_up (about 0.33 s), Gun_wind_down (about 1 s), Gun_muzzle_shake (looping), and the mesh Gun_barrel_blur.
  • [ ] Write tests/f15c-gun-spool.test.ts:
    • reaches full speed in about a third of a second: at 0.33 s, speed is within 2% of 100 / 6 * 2π.
    • barrels blur before they can alias: any speed moving a barrel more than 25° per frame at 60 fps has blur of 1.
    • a tap winds down from where it was: release at 0.1 s; the next step's speed changes by a small amount, with no jump to full speed or zero.
    • frame rate does not change the spin: speed after 0.2 s at 30 and 144 fps agrees within 2%.
    • a zero step changes nothing, which covers pausing.
    • the first round leaves on the trigger frame, via CannonSimulation.
    Run. Expected: fails, module missing.
  • [ ] Implement GunSpool reading curves sampled from the clips, with a fallback curve in code for tests. Replace the damping in effects.ts, keeping gunAngle and gunSpeed meaningful so tests/aircraft-preview.test.ts and replays hold.
  • [ ] Add blur crossfade, muzzle shake, and wind-down smoke using the existing discharge effect.
  • [ ] Run the new test with tests/f15c-cannon.test.ts, f15c-effects.test.ts, f15c-animation-regressions.test.ts, aircraft-preview.test.ts. Expected: all pass.
  • [ ] Capture video at 30, 60, 120 and 144 fps timing, close on the muzzle. Expected: no backward spin. Show the user.
