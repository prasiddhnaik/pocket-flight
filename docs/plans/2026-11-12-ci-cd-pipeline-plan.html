CI/CD pipeline implementation plan

Pocket Flight · 12 November 2026 · implements docs/plans/2026-11-12-ci-cd-pipeline-design.html

For agentic workers: execute task by task (superpowers:executing-plans or superpowers:subagent-driven-development). Read the design first. Work on branch ci-pipeline, never on main.

Summary

Goal: pull requests to main merge themselves only after GitHub Actions proves a clean build, the full test suite, pilot fit for all seven aircraft variants, and startup and flight in a real browser; main refuses everything else.

Approach: first make every existing check pass on a clean checkout. Then add one workflow with four jobs and a final required job, a strict mode for the fit tool covering the Finch and Heron, and a Playwright startup-and-flight script against the production build. Finally, switch on auto-merge and branch protection.

Tech: GitHub Actions, oven-sh/setup-bun, Bun 1.3.x, Vite 7 vite preview, Playwright Chromium with software WebGL, three.js geometry checks (existing scripts/fit/), gh CLI for repository settings.

Global constraints

  • Install everywhere with bun install --frozen-lockfile; build with bun run build (Vercel's commands, from vercel.json).
  • The checks only observe. No change to flight tuning, physics, visuals, aircraft or cockpit models.
  • No secrets or deploy tokens in GitHub. Vercel settings stay unchanged.
  • Every job runs on every pull request and push to main: no path filters, so the required check always reports.
  • Required status check name: CI passed. Merge method: squash. Protection includes administrators.
  • A failing check is fixed, never retried until green and never skipped. Do not add retries to tests.
  • Strict TypeScript, no any. Bun only (no npm or yarn).

Review focus

  1. Clean checkout missing git-ignored files. Expect a clear test failure naming the file, never a silent skip. Pinned by Task 1's clean-clone run.
  2. Slow software WebGL on runners. Expect the flight check to judge 20 seconds of simulated time with generous wall-clock limits, and to fail with "too slow to judge" rather than pass on too few frames. Pinned in Task 4.
  3. A docs-only or workflow-only pull request. Expect every job to still run and CI passed to report, so auto-merge neither stalls nor merges unchecked. Pinned in Task 2's workflow (no path filters) and Task 6's proof.
  4. A pull request from a fork (the repository is public). Expect the checks to run without secrets and nothing to merge without a maintainer turning on auto-merge. Pinned in Task 2: pull_request trigger only, read-only permissions.
  5. Harmless-looking console errors in the browser. Expect any pageerror or console.error to fail the run with its text. Fix the source; no allowlist. Pinned in Task 4.

Task 1: Every existing check passes on a clean checkout

Produces: fit maps at scripts/fit/maps/<id>.json for f15c, peregrine, stormbird and aurelia; load(id) in scripts/fit/load.ts reads them from there. A clean clone passes bun run build, bun run test and bun run fit all.

  • Clone the branch shallowly into a temp folder (git clone --depth 1 file://$PWD /tmp/pf-ci), run bun install --frozen-lockfile, bun run build, bun test ./tests and bun run fit all. Record every failure and every file it could not find. Expected: tests/cockpit-fit-map.test.ts fails, the fit tool reports "no fit-map", and possibly tests/heron-realism.test.ts and tests/f15c-flight.test.ts.
  • git mv is not possible for ignored files: copy each assets/<id>/cockpit/fit-map.json to scripts/fit/maps/<id>.json. Point build-cockpit.py's --fit-map output, load.ts and cockpit-fit-map.test.ts at the new path.
  • For each other failure, track the needed data next to its owner when it is under 1 MB, or change the test to build the data itself. Never make a test skip when a file is missing.
  • Repeat the clean-clone run. Expected: build passes; tests 0 fail; fit shows four NEAR PASS with "fit-map labels + surfaces".
  • Run bun run repo:check. Expected: OK.
  • Commit: "Make every check pass on a clean checkout".

Task 2: Workflow with build, tests and fit

Consumes: Task 1. Produces: workflow CI with jobs build, tests, fit, e2e (stub here, filled in by Task 4) and ci-passed (display name CI passed). Artifact dist uploaded by build.

  • Create .github/workflows/ci.yml: on: pull_request: branches: [main] and push: branches: [main]; permissions: contents: read; concurrency grouped by ref, with cancel-in-progress for pull requests only. Each job: actions/checkout@v4 with fetch-depth: 1, oven-sh/setup-bun@v2 with bun-version: 1.3.14, Bun install cache, bun install --frozen-lockfile, runs-on: ubuntu-latest.
  • build: bun run repo:check, bun run build, upload dist/ as artifact dist. tests: bun test ./tests, timeout 20 minutes. fit: bun run fit all, timeout 15 minutes (changed to --strict in Task 3).
  • ci-passed: needs: [build, tests, fit, e2e], if: always(); fails unless every needed job's result is success.
  • Push the branch and open a draft pull request. Expected: all jobs green on GitHub, and CI passed reported.
  • Commit: "Add CI workflow: build, tests, pilot fit".

Task 3: Fit check for the Finch, Finch attack and Heron, with a strict mode

Produces:

  • ids in limits.ts stays the cockpit list. New airframeIds = ["finch", "finch-attack", "heron"] as const and type AirframeId in scripts/fit/airframe.ts.
  • checkAirframe(id: AirframeId): Promise<AirframeReport>, with AirframeReport = { id: AirframeId; verdict: "PASS" | "NEAR PASS" | "REVIEW"; issues: string[]; seconds: number }, and airframeText(report: AirframeReport): string.
  • bun run fit <id|all> [--json] [--strict]: all covers the seven variants. --strict sets exit code 1 when any verdict is REVIEW.

Task 4: Startup and flight check in a real browser

Consumes: artifact dist (Task 2). Produces: bun run e2e [--base <url>] [--only <choice>]; default base http://127.0.0.1:4173. Screenshots go to output/e2e/<choice>-cockpit.png and -chase.png, and a summary to output/e2e/summary.json. Exit code 1 on any failure.

  • In App.tsx, set window.pocketFlight when import.meta.env.DEV || new URLSearchParams(location.search).has("e2e").
  • Add playwright to devDependencies at the version @playwright/cli already resolves in bun.lock.
  • Write scripts/e2e/startup-flight.ts. Launch Chromium headless with --use-angle=swiftshader --enable-unsafe-swiftshader --ignore-gpu-blocklist, viewport 1280×720. For each choice in ["finch", "finch-attack", "peregrine", "aurelia", "stormbird", "heron", "f15c"], in a fresh page:
    1. Open <base>/?e2e=1&aircraft=<choice>. Collect pageerror and console.error.
    2. Await pocketFlight.aircraft.ready and world.ready (timeout 180 s). Click the "Free flight" button and wait for mode === "playing". Await aircraft.pilot.ready and, if present, aircraft.interior.loaded.
    3. Startup passes when renderer.info.render.calls > 0 after 30 frames and the HUD is visible. Take the chase screenshot; switch cameraMode to "cockpit" and take the cockpit screenshot.
    4. Flight: record start altitude (physics.position.y), hold ShiftLeft for 3 s of simulated time, then hold ArrowDown lightly (key down 0.3 s of every 1 s) until 20 s of simulated time have passed, measured from the game's own clock. Wall-clock limit 240 s. If fewer than 200 frames are rendered, fail with "too slow to judge".
    5. Flight passes when, at every sampled frame: position, velocity and quaternion are finite; mode === "playing" (no crash); altitude ≥ start − 50 m; speed (physics.velocity.length()) ≥ 0.9 × physics.stallSpeed; |roll| < 1.2 rad.
    Write per-choice results and errors to summary.json; print one line per choice.
  • Run locally against the production build: bun run build && bunx vite preview --port 4173 &, then bun run e2e. Expected: seven PASS lines and 14 screenshots. Then break it on purpose (--only finch with an injected throw in the console via page.evaluate in a scratch run). Expected: FAIL with the error text. Revert the scratch change.
  • Fill in the workflow's e2e job: download dist, install Chromium (bunx playwright install --with-deps chromium, cached), start bunx vite preview --port 4173 --strictPort in the background, wait for the port, run bun run e2e, and upload output/e2e/ as artifact e2e-screenshots with if: always(). Timeout 30 minutes.
  • Push. Expected: e2e green on GitHub, artifact with 14 screenshots, whole run under 15 minutes. If e2e fails only on GitHub, treat it as a real finding (often frame-time dependence) and report it to the owner. Do not loosen the bounds.
  • Commit: "Browser startup and flight check for all aircraft".

Task 5: Lock main, auto-merge, working rules

  • Update AGENTS.md: replace "a push to main deploys to production. Push only when the user asks" with: never push to main; branch, open a pull request, run gh pr merge --auto --squash, and watch it until it merges; fix failures on the branch. Update the README Hosting section to match, and list the four checks with their local commands (bun run build, bun run test, bun run fit all --strict, bun run e2e).
  • Run bun run repo:check and bun test tests/documentation.test.ts. Expected: pass. Commit: "Document the pull-request workflow".
  • Confirm with the owner before changing repository settings, then run: 
    gh api -X PATCH repos/prasiddhnaik/pocket-flight -F allow_auto_merge=true -F delete_branch_on_merge=true -F allow_squash_merge=true
gh api -X PUT repos/prasiddhnaik/pocket-flight/branches/main/protection --input - <<'JSON'
{"required_status_checks":{"strict":false,"contexts":["CI passed"]},
 "enforce_admins":true,
 "required_pull_request_reviews":null,
 "restrictions":null,
 "allow_force_pushes":false,
 "allow_deletions":false}
JSON
    Required reviews stay off, because auto-merge with no second reviewer is the owner's choice. Pull requests are still required: direct pushes fail because the status check cannot be met by a push.
  • Verify: gh api repos/prasiddhnaik/pocket-flight/branches/main/protection --jq '.required_status_checks.contexts, .enforce_admins.enabled'. Expected: ["CI passed"] and true. git push github HEAD:main from a scratch commit is refused (then drop the scratch commit).
  • Mark the ci-pipeline pull request ready and turn on auto-merge. Expected: it merges itself once green, and Vercel publishes it.

Task 6: Prove it

  • Open pull request "CI proof: deliberate failure" that changes one assertion in tests/pilot.test.ts to fail, and turn on auto-merge. Expected: tests fails, CI passed fails, and it does not merge. Close it without merging and delete the branch.
  • Open pull request "CI proof: docs-only" that fixes a typo in the README, with auto-merge. Expected: every job runs, it merges itself, and the Vercel production deployment for the merge commit reaches READY.
  • Write output/reports/ci-cd-pipeline-2026-11-12.html from docs/REPORT_TEMPLATE.html: run times per job, links to both proof pull requests, and any checks not run.
